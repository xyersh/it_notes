## Модели репликации:
- Master-Slave - данные записываются в master, а затем дублируются из мастера в slave (синхронизация)
- Master-Master - данные могут писаться в несколько реплик (master). синхронизация синхронная.
  

## Виды репликации:
- синхронная - данные сразу передаются из master в slave
- асинхронная - данные  передаются из master в slave когда-то потом. (данная репликация используется для аналитики, отчетов, аудита)  

реплик у мастера  может быть много
самих мастеров может быть много 

Репликация не решает в полной мере вопросов масштабирования (антипаттерн):
- если нагрузка на чтение большая то масштабировать можно добавлением реплик (slave)
- однако, этот вопрос можно закрыть использованием кэша вместо репликации
- придется выбирать компромисс между доступностью и согласованностью

Основная задача репликации - достижение отказоустойчивости

## Физическая репликация
Физическая репликация - поблочно копируются сырые байты
Плюсы:
- Быстро работает
- базы идентичны 1 в 1
- просто применить изменения к реплике
Минусы:
- часто копирование избыточных данных
- на реплике нельзя создавать новые сущности
- на время репликации данных все транзакции на реплике должны быть остановлены


## Логическая репликация
Логическая репликация - копируются только изменения  (insert на мастере -> insert на реплике)
Плюсы:
- передаются только данные
- во время репликации транзакции на реплике могут продолжаться без проблем
- на реплике можно добавлять новые сущности
- можно построить систему с несколькими мастерами

Минусы:
- более медленная
- транзакции могут проходить с задержками
- сложнее
