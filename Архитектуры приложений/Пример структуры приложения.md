## Пояснения  к диаграмме
- каждый прямоугольник - это папка
- структура папок в приложении соответствует расположению структруре расопложения прямоугольников
- **cmd** - содержит в себе файлы запускаторов. Их может быть более одного, как как один проект может использоваться для получения несколькольих приложений
- **internal** -сердце проекта.
	- **reatures** - содержит файлы приложений со всеми необходимыми слоями, также аккуратно раскинутым по соответсnвующим папкам (transport, service, repository)
		- **dto** - сущности только для транспортного слоя 
		- **model** - сущности только репозиторного слоя
		- **transport** - для связи приложения с внешним миром
		- **service** - сюды бизнес-логика
		- **repository** - для хранения данных
	- **core** - хранит в себе функционал и сущности, которые могут быть использованы во всех фичах/приложениях проекта. Определены в одном месте - используются везде
		- **domains** - здеся лежат реализации сущностей доменной области (один домен может дергаться несколькими приложениями по разным причинам и назначениям)
		- **logger** - реализация логгера
		- **config**
		- **error** - здеся самописные определены ошибки, которые используются приложением
		- **tools** - всякие полезные штуки неопределнного назначения 
- **pkg** - используется для генерации подгорания пуканов у любителей поспорить о назначении папки **pkg**. 
- **migration** - сюды файлы миграции
- **out** - здеся живуть логи и всякие там докеровские волюмы
- ... и прочие файлы в корне проекта тоже нужны


## Именование 
Дизайн проекта не регламентирует строгие правила именования директорий - папки могут называться по всякому
