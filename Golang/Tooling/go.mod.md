`go.mod` — это манифест-файл, определяющий **модуль** (module). Модуль в Go — это набор пакетов, распространяемых и версионируемых вместе. Файл хранится в корне репозитория и содержит:

- путь к модулю (обычно совпадает с URL репозитория)
- минимальную версию Go
- прямые и транзитивные зависимости
- дополнительные директивы (`replace`, `exclude`, `retract`, `tool`)

Рядом с ним автоматически создаётся `go.sum` — файл с криптографическими хешами всех загруженных модулей, гарантирующий воспроизводимость сборок.


## Преимущества использования `go.mod`
| Преимущество                      | Описание                                                                                                                   |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **Воспроизводимость сборок**      | Комбинация `go.mod` + `go.sum` гарантирует, что все разработчики и CI собирают проект с одинаковыми версиями зависимостей. |
| **Независимость от `GOPATH`**     | Проект можно размещать в любой директории файловой системы.                                                                |
| **Семантическое версионирование** | Встроенная поддержка `vX.Y.Z`, диапазонов версий, минимального выбора версий (Minimal Version Selection).                  |
| **Прозрачный граф зависимостей**  | Чёткое разделение на прямые (`require`) и косвенные (`// indirect`) зависимости.                                           |
| **Гибкое переопределение**        | Директивы `replace`, `exclude`, `retract` позволяют решать сложные кейсы без форков.                                       |
| **Интеграция с инструментами**    | `go test`, `go build`, `go vet` и другие команды автоматически работают с модулями.                                        |

## Структура и синтаксис `go.mod`
```go.mod
module github.com/user/myapp

go 1.22

require (
    github.com/gin-gonic/gin v1.9.1
    golang.org/x/crypto v0.14.0 // indirect
    google.golang.org/grpc v1.58.2
)

replace github.com/old/pkg => github.com/new/pkg v1.0.0

exclude github.com/unmaintained/bad v1.2.3

retract [v1.0.0, v1.0.1]

tool golang.org/x/tools/cmd/goimports
```

### Разбор директив:

- `module` — уникальный путь модуля. Должен быть валидным URL-подобным идентификатором.
- `go` — **минимальная версия Go**, требуемая для сборки. С Go 1.21 также управляет поведением тулчейна.
- `require` — список зависимостей. `// indirect` означает, что пакет не импортируется напрямую в вашем коде, но нужен транзитивным зависимостям.
- `replace` — локальное или удалённое переопределение модуля (полезно для разработки локальных форков).
- `exclude` — запрещает использование конкретной версии модуля в графе зависимостей.
- `retract` — помечает версии как отозванные (рекомендуется не использовать).
- `tool` (Go 1.23+) — объявляет инструменты, необходимые для разработки (линтеры, генераторы и т.д.).

## Основные команды и примеры
### 1. Инициализация модуля
```bash
go mod init github.com/username/project
```
Создаёт `go.mod` с указанием пути модуля и текущей версии Go

### 2. Добавление/обновление зависимости
```bash
go get github.com/gin-gonic/gin@v1.9.1
go get github.com/sirupsen/logrus@latest
```

Обновляет `go.mod` и `go.sum`. **Важно:** начиная с Go 1.16 `go get` не собирает проект, а только управляет зависимостями.

### 3. Очистка и синхронизация
```bash
	go mod tidy
```
Самая используемая команда:
- Добавляет отсутствующие зависимости
- Удаляет неиспользуемые
- Обновляет `go.sum`
- Применяет `replace`/`exclude` к графу

### 4. Загрузка зависимостей в кеш
```bash
go mod download
go mod download github.com/gin-gonic/gin@v1.9.1
```
Кэширует модули в `$GOPATH/pkg/mod`. Полезно в CI для ускорения последующих сборок.


### 5. Проверка целостности
```bash
go mod verify
```
Сравнивает хеши загруженных модулей с `go.sum`. Выдаст ошибку при расхождении.


### 6. Вендоринг (локальное копирование)
```bash
go mod vendor
```
Копирует все зависимости в директорию `vendor/`. Сборка с `GOFLAGS=-mod=vendor` не требует доступа к интернету.


### 7. Инспекция графа зависимостей
```bash
go list -m all                 # все модули с версиями
go mod graph                   # визуальный граф зависимостей
go mod why github.com/pkg/errors  # почему модуль оказался в зависимостях
```


## Лучшие практики
| Практика                                                 | Почему это хорошо                                                                                                   |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| **Коммитьте `go.mod` и `go.sum` вместе**                 | Без `go.sum` сборки не будут детерминированными.                                                                    |
| **Запускайте `go mod tidy` перед коммитом**              | Избегает накопления "мусорных" зависимостей.                                                                        |
| **Используйте `GOFLAGS=-mod=readonly` в CI**             | Гарантирует, что CI не сможет молча изменить `go.mod` при нехватке зависимостей.                                    |
| **Избегайте `replace` в публичных библиотеках**          | `replace` не публикуется в `proxy.golang.org`. Для библиотек он должен быть только в `go.mod` конечного приложения. |
| **Обновляйте зависимости регулярно, но проверяйте**      | `go get -u ./...` обновит всё до последних совместимых версий. Обязательно прогоняйте тесты.                        |
| **Понимайте `// indirect`**                              | Это не ошибка. Go автоматически помечает транзитивные зависимости. Не удаляйте их вручную.                          |
| **Указывайте актуальную `go` директиву**                 | С Go 1.21 она задаёт **минимальную** версию. Указывайте ту, с которой гарантированно работает проект.               |
| **Используйте `go mod vendor` только при необходимости** | Обычно кеш модулей и `go.sum` достаточно. Вендор нужен только для оффлайн-сборок или особых политик безопасности.   |

## Типичные проблемы и решения
| Симптом                                               | Причина                                             | Решение                                                                 |
| ----------------------------------------------------- | --------------------------------------------------- | ----------------------------------------------------------------------- |
| `missing go.sum entry for module...`                  | `go.sum` не синхронизирован                         | `go mod tidy`                                                           |
| `module declares its path as X but was required as Y` | Путь в `go.mod` не совпадает с импортом             | Проверьте `module` в `go.mod` и пути импортов                           |
| Зависимость обновляется до непредсказуемой версии     | Отсутствие `go.sum` или `replace`                   | Закоммитьте `go.sum`, используйте `@vX.Y.Z`                             |
| `go mod tidy` удаляет нужную зависимость              | Пакет импортируется только в тегах/билд-констрактах | Используйте `//go:build` корректно или добавьте явный импорт в `doc.go` |
