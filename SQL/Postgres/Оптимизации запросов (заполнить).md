### Анализ плана выполнения

Планировщики в Postgres:
- эвристический
- стоимостной

**EXPLAIN** - получение предположительной оценки выполнения запроса (только на основании имеющейся статистики):
- не выполняет запрос
- показывает оценку **cost**
- показывает ожидаемые **rows**
Оценка получается приближенной, порой - неверной
```SQL
EXPLAIN
SELECT *
FROM
WHERE
```


**EXPPAIN ANALIZE** - фактическая оценка выполнения запроса (Запрос выполняется)
Более точная оценка.
- выполняет запрос 
- показывает actual time
- показывает actual rows, loops
```SQL
EXPLAIN ANALIZE
SELECT
FROM 
WHERE
```

#### Чтение плана
- сначала смотрим на тип узла:
	- cost - внутренняя оценка в безразмерных единицах (не милисекунды)
	- rows - ожидаемое количество строк
	- width - средний размер строки, влияющий на стоимость передачи и сортировки
	
- сравниваем actual time, actual rows  и Loops
	- **actual time** - время  первого и последнего результата узла
	- **actual rows** - фактическое количество строк за 1 **loop**
	- **loops** - сколько раз узел запускался родительским узлом. Большое значение **loops** может стать проблемой

- проверка **estimated rows VS actual rows**. Когда предполагаемая оценка строк отличается от фактического количества строк - все остальные решения плана становятся подозрительными.  Стоит задуматься о правильности работы плана.

#### Причины плохих оценок
- Статистика  не актуальна - **ANALIZE** давно не запускался после изменения данных
- Распределение - если значения перекошены - оценка может быть неправильной
- Связанные условия -
- Параметры - запрос получает значения с разной селективностью
