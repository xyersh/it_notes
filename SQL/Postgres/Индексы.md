### B-Tree (Индекс по сбалансированному дереву)
Тип по умолчанию. Поддерживает операторы `<`, `<=`, `=`, `>=`, `>`, `BETWEEN`, `IN`, `IS NULL`.
```sql
-- Создание (USING btree можно не писать, это дефолт)
CREATE INDEX idx_users_email ON users USING btree (email);

-- Использование
SELECT * FROM users WHERE email = 'test@example.com';
SELECT * FROM users WHERE created_at > '2023-01-01';
```


### GIN (Generalized Inverted Index / Инвертированный индекс)
Идеален для составных типов данных: **JSONB**, массивы, полнотекстовый поиск. Индексирует каждое отдельное значение/ключ внутри структуры.
```sql
-- Создание для JSONB
CREATE INDEX idx_users_data_gin ON users USING gin (data_jsonb);

-- Использование (поиск внутри JSON)
SELECT * FROM users WHERE data_jsonb @> '{"role": "admin"}';

-- Создание для массивов
CREATE INDEX idx_tags_gin ON articles USING gin (tags);
-- Использование: поиск строк, где массив содержит элемент
SELECT * FROM articles WHERE tags @> ARRAY['database'];
```


### GiST (Generalized Search Tree)
Используется для геометрических данных, полнотекстового поиска (tsvector), типов диапазонов (range types).
```sql
-- Создание для полнотекстового поиска
CREATE INDEX idx_docs_search ON documents USING gist (to_tsvector('russian', content));

-- Использование
SELECT * FROM documents WHERE to_tsvector('russian', content) @@ to_tsquery('база & данных');

-- Создание для геометрических данных (PostGIS)
CREATE INDEX idx_geom_gist ON locations USING gist (geom);
-- Использование: поиск точек в радиусе
SELECT * FROM locations WHERE ST_DWithin(geom, ST_MakePoint(37.61, 55.75), 1000);
```


### BRIN (Block Range Index)
Очень маленький и быстрый индекс для огромных таблиц, где данные физически отсортированы в порядке возрастания (например, `created_at` или `id`). Индексирует не каждую строку, а мин/макс значения для групп блоков.
```sql
-- Создание
CREATE INDEX idx_logs_created_brin ON logs USING brin (created_at);

-- Использование (работает быстро, если данные вставлялись хронологически)
SELECT * FROM logs WHERE created_at BETWEEN '2023-10-01' AND '2023-10-02';
```



### Hash Index
Индекси только для простых операций равенства (`=`). В современных версиях PG B-Tree обычно работает не хуже, поэтому Hash используется редко.
```sql
-- Создание
CREATE INDEX idx_users_hash ON users USING hash (session_token);

-- Использование
SELECT * FROM users WHERE session_token = 'abc123';
```


### Partial Index (Частичный индекс)
Особенность PostgreSQL (и Oracle тоже, но в PG это очень популярно). Индексирует не всю таблицу, а только строки, удовлетворяющие условию `WHERE`.
```sql
-- Создание (индексируем только активных пользователей)
CREATE INDEX idx_users_active ON users (email) WHERE is_active = true;

-- Использование (запрос ДОЛЖЕН содержать условие из WHERE индекса)
SELECT * FROM users WHERE is_active = true AND email = 'test@example.com';
```
