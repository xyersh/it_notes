
Инструмент использующийся для управлением блокировок строк на изменение.
Применяется в конструкции **SELECT**
Блокировка строк происходит на время исполнения запроса **SELECT** с  **FOR UPDATE**

## КЛЮЧЕВЫЕ ПРИНЦИПЫ 
- Базовый синтаксис:
```sql
SELECT*
FROM table_name
WHERE ...
FOR UPDATE
```
- **Читающие не блокируют пишущих, пишущие не блокируют читающих.**
	- Обычный `SELECT` всегда читает согласованный снимок данных (через Undo), игнорируя TX-блокировки.
	- `FOR UPDATE` блокирует строки **только** для других `UPDATE`, `DELETE`, `MERGE` и `SELECT ... FOR UPDATE`
- **Блокировка привязана к ТРАНЗАКЦИИ, а не к коду**
	- конструкции `SELECT ... FOR UPDATE` являются DML операциями. 
	- Захваченная блокировка снимается **только** по `COMMIT` или `ROLLBACK`.
	- Завершение функции/процедуры/курсора — **НЕ снимает** блокировку.
	- Закрытие курсора — **НЕ снимает** блокировку.
	- Завершение сессии — снимает (через неявный ROLLBACK).
-  **Блокировка ставится на ФИЗИЧЕСКИЕ строки**
	- `FOR UPDATE` работает только с реальными строками таблиц.
	- Невозможно заблокировать агрегат, группу, виртуальный результат.
-  **Ограничения на использование**
	- `FOR UPDATE` **нельзя** применять, если на уровне использования FOR UPDATE в запросе есть:
		- `GROUP BY` и агрегатные функции (`SUM`, `COUNT`, `MAX`...)
		- `DISTINCT`
		- `UNION`, `INTERSECT`, `MINUS`
		- `CONNECT BY` (иерархии)
		- Аналитические функции (`ROW_NUMBER`, `RANK`...)
		- Рекурсивные CTE
- **`FOR UPDATE OF` — для JOIN'ов**
	- Без `OF` блокируются строки **во всех** таблицах запроса.
	- С `OF table.column` — только в указанной таблице.
	- В CTE и подзапросах работает так же.
-  **Позиция в запросе**
	- `FOR UPDATE` всегда **в самом конце** `SELECT`.
	- Внутри CTE / подзапросов — **нельзя**.





## FOR UPDATE не применим если:
присутствует некая неопределенность, какие строки требуют блокировки
Такое возможно, если в запросе есть:
- **Агрегатные функции и группировка:** 
```sql
SELECT SUM(salary) FROM employees FOR UPDATE
```
- **Операции над множествами (Set Operators):** `UNION`, `UNION ALL`, `INTERSECT`, `MINUS`
- **Ключевое слово `DISTINCT`:**
- **Скалярные подзапросы в списке:**
	```sql
	`SELECT (SELECT name FROM dual) as val --скалярный подзапрос 
	FROM t FOR UPDATE`
	```
- **Псевдостолбцы `LEVEL`, `ROWNUM` (в некоторых контекстах):**
  Часто запрещено в иерархических запросах (`CONNECT BY`).
- **Только для чтения (Read Only):**
	- Если представление (VIEW) создано с опцией `READ ONLY`.
	- Если таблица внешняя (External Table).
- **Выборка из `SAMPLE`:**
```sql
SELECT * FROM t SAMPLE (10) FOR UPDATE
``` 


## Правила использования FOR UPDATE

#### 1. Указывать таблицу (`OF`)
Если используется `JOIN` нескольких таблиц, лучше указать, строки какой именно таблицы вы хотите заблокировать. Это снижает риск блокировок и делает намерения явными.
Если блокируем меньше таблиц, вероятность того, что два процесса заблокируют ресурсы в разном порядке и встанут в тупик, снижается.
Указывать нужно именно столбец, но блокируется вся строка таблицы, которой принадлежит этот столбец.
```sql
-- Блокируем строки только в таблице accounts, а не в joined таблицах
SELECT a.id, b.name
FROM accounts a
JOIN clients b ON a.client_id = b.id
FOR UPDATE OF a.id; 
```
В данном примере блокируется только таблица accounts. Это позволит другим пользователям работать со справочником клиентов, пока мы обрабатываем счета.

#### 2. Использовать `NOWAIT` или `WAIT`
По умолчанию, если строка уже заблокирована другой сессией, ваш запрос "зависнет" и будет ждать вечно (пока та сессия не сделает коммит). В скриптах это опасно.
- `NOWAIT`: Если строка занята, сразу выдать ошибку `ORA-00054`.
- `WAIT n`: Ждать блокировку не более `n` секунд.
- `SKIP LOCKED`: (Очень полезно для очередей) Пропустить заблокированные строки и взять следующие свободные.
```sql
SELECT * FROM accturn 
WHERE account_id = 123 
FOR UPDATE NOWAIT; 
```

#### 3. Держать транзакцию короткой
Не стоит делать `SELECT ... FOR UPDATE`, а потом запускать долгие вычисления в PL/SQL или ждать ввода пользователя. Строки будут заблокированы для всех остальных.
```sql
-- ПЛОХО
SELECT ... FOR UPDATE; -- Заблокировал
DBMS_LOCK.SLEEP(100);  -- Жду 100 секунд (все остальные ждут!)
COMMIT;

-- ХОРОШО
SELECT ... FOR UPDATE;
-- Сразу UPDATE/INSERT
COMMIT;
```



## BEST PRACTICES

### Всегда используйте `NOWAIT` или `WAIT N`
```sql
FOR UPDATE NOWAIT      -- мгновенная ошибка ORA-00054
FOR UPDATE WAIT 5      -- ждать 5 сек, затем ORA-30006
```
- "Голый" `FOR UPDATE` может повиснуть навечно.
- Всегда обрабатывайте исключения в коде.

### Минимизируем время удержания
- **Плохо:** `FOR UPDATE` в начале долгого процесса.
- **Хорошо:** блокировать как можно ближе к `UPDATE`/`COMMIT`.
- Долгая блокировка = очереди, deadlocks, разрастание Undo.

### Разделяем чтение и блокировку
- Сложная аналитика / `GROUP BY` / CTE — сначала читаем.
- Потом короткий `SELECT ... FOR UPDATE` по найденным `ID`.
- Потом быстрый `UPDATE` и `COMMIT`.

### Явное управление транзакцией
```sql
BEGIN
   -- SELECT ... FOR UPDATE
   -- бизнес-логика
   COMMIT;              -- ← обязательно
EXCEPTION
   WHEN OTHERS THEN
      ROLLBACK;         -- ← обязательно
      RAISE;
END;
```
- Без `COMMIT` блокировка "утечет" до конца сессии.
- Без `ROLLBACK` в EXCEPTION блокировка тоже останется.


## Типичные ловушки
### Вызов функции с `FOR UPDATE` из SQL

- Функция, вызванная из `SELECT ... FROM dual`, выполняется в **рекурсивной транзакции**.
- Oracle делает неявный `COMMIT` сразу после SQL-предложения.
- **Блокировка снимается мгновенно** — функция бесполезна.
- **Решение:** вызывать только из PL/SQL или использовать `DBMS_LOCK`.


### Неявный COMMIT от DDL
- Любая DDL (`CREATE`, `ALTER`, `TRUNCATE`, `DROP`) делает неявный `COMMIT`.
- Если вы заблокировали строки, а потом выполнили DDL — блокировка снимется.

### Deadlocks

- Возникают, когда две сессии блокируют одни и те же ресурсы в разном порядке.
- Oracle сам обнаруживает deadlock и откатывает одну транзакцию (`ORA-00060`).
- **Профилактика:** всегда блокировать строки в одном и том же порядке (например, по `ID`).

### Блокировка "лишних" таблиц

- При `JOIN` без `FOR UPDATE OF` блокируются все таблицы.
- Можно случайно заблокировать справочник, который не планировали менять.
