## Мета-символы 
Метасимволы имеют специальное назначение в реджекспах, в зависимости от их расположения в шаблонах.
Для использования спец-символов в качестве литералов требуется:
- размещать их в тех местах шаблона, где движок распознает их как литералы
- экранирование спец-символов с применением `\`

`^`, `$`, `[`,  `]`,`.`,  `{`, `(`, `)`, `-`, `+`,  `*`, `\`, `|`, `?`,`!`, `=`, `<`,  `>`

## Кванторы (квантификаторы)
Определяют количество вхождений символов в строке для соблюдения условия соответствия строки шаблону
Кванторы бывают:
- жадными - движок регулярных выражений будет стремиться захватить максимально длинную подстроку, удовлетворяющую шаблону
- ленивыми - захватывают минимально возможное количество символов, чтобы выражение нашлось, и останавливаются при первом же совпадении

| `*?`     | {0,}?   | 0 или больше, нежадный + |
| `+`      | {1,}    | 1 или больше +           |
| `+?`     | {1,}?   | 1 или больше, нежадный + |
| `?`      | {0,1}   | 0 или 1 +                |

### Определение наборов в квадратных скобках

Диапазоны символов можно указывать в квадратных скобках.
`[abc]` - соответствует буквам a, b, c
`[a-z]` - все строчные символы английской раскладки
`[а-яё]` - все строчные символы кириллической раскладки

В общем случае, символы помещенные в `[]` ведут себя как обычные литералы и теряют свое функциональное назначение. Однако имеется ряд символов, имеющих специальное назначение внутри квадратных скобок


Спецсимволы

| Символ | Спец назначение                         | Условие использования с качестве спецсимвола    |
| ------ | --------------------------------------- | ----------------------------------------------- |
| `-`    | Определяет диапазон допустимых символов | располагать между символами, являющимися границей диапазона                                                |
| `^`    | Инверсия                                | располагать сразу после открывающей скобки `[^` |

Как литералы:
- `^`(гравис) - располагать в любом другом месте, кроме начала (`[wer^we]`, `[fsdf^]`)
- `-`(дефис) - располагать в начале или конце набора (`[-adasd]`, `[123-]`)
- `[`, `]` - любое неожиданное для парсинга место (`[][]`)
Чтобы использовать ^, - как литералы - можно использовать экранирование с использованием `\`. Так например экранирование `\^`, `\-`, `\[`, `\]`, `\\` всегда использование символов, как литералы.

## Захватывающие и незахватывающие группы

Для определения групп используются скобки `(`, `)` с определением внутри них содержимым
Круглые скобки в регулярных выражениях выполняют две задачи. 
-  группировка, она позволяет применить оператор или квантификатор не к одному, а к целой последовательности символов. Эдакий выбор альтернативы. `(hello|привет)` - для выбора между "hello" и "привет"
-  захват (capturing) - для дальнейшего использования полученных "снимков" в другом месте шаблона, или получения значения внутри группы посредством обратных ссылок.


> По умолчанию группы являются захватывающими.

Каждая захватывающая группа получает свой порядковый номер. Последовательность начинается с единицы и определяется положением открывающей скобки в шаблоне, слева направо.

Например, в выражении `(a(b(c)))d` будет три группы:
- первая захватит `abc` (внешние скобки),
- вторая — `bc` (вложенные),
- третья — лишь `c` (внутренние).

На захваченные группы можно указывать прямо внутри самого регулярного выражения. Для этого существуют обратные ссылки (backreferences), которые выглядят как `\1`, `\2`, `\3` и так далее, где цифра — это номер захватывающей группы. Такая конструкция приказывает движку: «Найди здесь точно такой же текст, который был захвачен группой с номером N».

> Например, задача: нужно найти слово, за которым после одного или нескольких пробелов следует точно такое же слово.
> решается выражением `(^|\s)([a-zA-Zа-яА-ЯЁ0-9_]+)\s+\2(\s|$)`



### Незахватывающие группы
Если группы используются только для выбора альтернативы и захват значения является лишь паразитной работой  - используются незахватывающие группы.
``(?:шаблон группы)``

Использование незахватывающих групп имеет несоклько преимуществ:
- **Чистота кода** Когда вы пишете сложный шаблон для извлечения данных, в нем может быть много групп. Некоторые из них — ключевые (например, имя пользователя, дата), а другие — вспомогательные, нужные только для логики. Использование вспомогательных/незахватывающих групп избавляет от «мусора» в результатах. Если вам нужна третья по счету значимая часть данных, вы получите к ней доступ как `\3`, а не как `\7` — из‑за того, что перед ней были еще четыре служебные группы.
- **Производительность**. Каждая захватывающая группа требует от движка выделить память и сохранить найденную подстроку. На очень больших текстах и в по‑настоящему сложных выражениях отказ от ненужных захватов может дать на горячих путях небольшое, но заметное ускорение.
- **Семантика** - задается явное намерение использования группы как выбора альтернативы, захват значения при этом не требуется.

### Именованные захватывающие группы
`(?<имя_группы>содержимое шаблона)`
Использование именованных групп позволяет избавиться от недостатков использования позиционных групп.
Например для строки:
```
Date: 2025-06-05; User: admin;
```
 вместо шаблона с позиционными группами
 ```
 Date: (\d{4}-\d{2}-\d{2}); User: (\w+);
 ```
можно воспользоваться 
```
Date: (?<date>\d{4}-\d{2}-\d{2}); User: (?<user>\w+);
```
Далее, на эти группы можно ссылаться по имени ('date', 'user').



## Утверждения (lookarounds)
позволяют движку «бросить взгляд» вперед или назад от текущей позиции в строке. При этом удается проверить, соответствует ли текст определенному шаблону, и на основе этого принять решение — продолжать поиск или нет. Самое главное: текст, на который «посмотрели», не становится частью итогового совпадения — курсор движка не перемещается.

Таких конструкций 4:
- Позитивный просмотр вперед
- Негативный просмотр вперед
- Позитивный просмотр назад
- Негативный просмотр назад

### Позитивный просмотр вперед
Конструкция `(?=)` говорит движку: «Посмотри вперед. Продолжи работать, только если за этой точкой следует текст, соответствующий шаблону внутри скобок».
> Пример: определенить соотвествует ли введенный пароль требованиям: не менее 8 символов, должно быть хотя бы один числовой литерал
 ```
 ^(?=.*\d{2,}).{8,}$
 ```

- `^` — якорь начала строки.
- `(?=.*\d)` — вот и наша магия, позитивный просмотр вперед. Он, не сдвигая курсор с начала строки, «смотрит» вправо и проверяет, есть ли где-то дальше `.*` хотя бы одна цифра `\d`. Если да, утверждение истинно, и движок продолжает работу. Если нет, вся строка считается не соответствующей шаблону. Важно: эта проверка не «съедает» символы.
- `.{8,}` — если проверка пройдена, основной шаблон продолжает работу с того же места, где остановился (то есть с начала строки). Требуется наличия не менее восьми любых символов.
- `$` — якорь конца строки.


### Негативный просмотр вперед

Конструкция `(?!)` — полная противоположность предыдущей. Она говорит движку: «Посмотри вперед. Продолжи работать, только если за этой точкой нет текста, соответствующего шаблону внутри скобок».

>Предположим, нам нужно найти все формы слова «кот», за которыми не следует союз «и». Примеры: «кот.», «кот,», «кот!», но не «кот и кошка». Вы, наверное, уже быстро написали в уме:
```regexp
(?:^|\s)кот(?!\sи[^а-яё])
```


### Позитивный просмотр назад
Конструкция `(?<= )` говорит движку: «Продолжай поиск, только если этому месту предшествует текст, соответствующий шаблону».

> Пример: найдем все цены в долларах (знак  `$` в тексте предваряет значение стоимости: `...$100500...` ) При этом сам значок `$` в результаты попадать не должен.

```regexp
(?<=\$)\d+
```

## Модификаторы шаблонов
- **g**  - (**global**) Глобальный поиск. активирует глобальный режим. По умолчанию движок останавливается после нахождения первого совпадения. С флагом `g` поиск продолжается по всему тексту до его конца, и в результат попадают все найденные совпадения.
- **i** - (**case-insensitive**) Регистронезависимый шаблон. включает режим нечувствительности к регистру символов — например, выражение cat найдет и cat, и Cat, и CAT. Подобное поведение относится только к буквам — спецсимволы, такие как `\s` и `\S`, продолжают работать привычным образом.
- **m** - (**multiline**) Многострочный текст. активирует многострочный режим. Эта опция изменяет поведение якорей `^` и `$`. В обычном режиме `^` соответствует только началу всего текста, а `$` — только его концу. В режиме `m` якорь `^` также соответствует началу каждой новой строки (сразу после символа `\n`), а `$` — концу каждой строки (непосредственно перед символом `\n`).
- **s** - (**single line или dotall**) Считать текст одной строкой. изменяет поведение метасимвола точки (`.`). Исторически точка соответствует любому символу, кроме переноса строки. Включение опции `s` «исправляет» это, заставляя точку соответствовать абсолютно любому символу, даже `\n`. Опции `s` и `m` не являются взаимоисключающими и могут быть активны одновременно.

## ПРИМЕРЫ ЗАДАЧ


### Базовый синтаксис

#### 1. Поиск года
Найдите все годы в историческом тексте.
Текст проверки:
```
The document was dated 1812. It mentions events from 1789 and 1805. The author, born in 1770, lived for 67 years. The total cost was 1200 gold coins. Chapter 5 describes the battle.
```
Решение:
```regexp
\d{4}
```


#### 2. Символьные классы
Напишите регулярное выражение, которое найдет все гласные буквы в русском тексте.
Текст проверки:
```
Ау, я иду! Эхо унесло её крик в ущелье. Оаэ, ау! Это было странное эхо.
```
Решение:
```regexp
[а-яёА-ЯЁ]
```

#### 3. Необязательные символы
Вы обрабатываете текст, который сочетает как американское, так и британское написание. Напишите регулярное выражение, которое находит и «color», и «colour».
Текст проверки:
```
The color of the flag is red. My favourite colour is blue. This is a colorful painting. What color do you prefer?
```
Решение:
```regexp
colou?r
```


#### 4. Группировка альтернатив
Найдите в тексте полные приветствия «Добрый день» и «Добрый вечер».
Текст проверки:
```
Добрый день, коллеги! Начинаем наше совещание. Добрый вечер. Завтра утром будет хорошая погода, а вот вечер обещает быть дождливым.
```
Решение:
```regexp
Добрый +(?:день|вечер)
```


#### 5. Поиск фразы
Напишите регулярное выражение, которое найдет в тексте все словосочетания про… регулярные выражения. При составлении решения учитывайте, что регистр букв разный, а кое‑где встречаются двойные пробелы.
Текст проверки:
```
Регулярные выражения — это мощный инструмент. Каждое регулярное  выражение представляет собой шаблон для поиска. Изучать регулярные выражения интересно.
```
Решение:
```regexp
(Р|р)егулярн\S+\s+выражен\S+
```


### Управление поиском

#### 6. Валидация всей строки
Найдите строки, которые включают слово «SUCCESS» и ничего больше.
Текст проверки:
```
SUCCESS  
ATTEMPT FAILED, BUT… SUCCESS  
IN_PROGRESS  
SUCCESS!
```
Решение:
```regexp
^SUCCESS$
```



#### 7. Жадность и лень
Извлеките содержимое всех тегов `<b>` из фрагмента HTML. Напишите регулярное выражение, которое правильно обрабатывает несколько тегов в одной строке.
Текст проверки:
```
This is <b>important</b> and this is <b>also important</b>.
```
Решение:
```r
(?<=<b>).*?(?=<\/b>)
```


#### 8. Встроенные классы символов
В лог-файле события записываются с меткой времени в формате `ГГГГ-ММ-ДД ЧЧ:ММ:СС`. Напишите лаконичное регулярное выражение для поиска таких меток.
Текст проверки:
```
[2023-10-26 15:30:01] User ‘admin’ logged in.  
[2023-10-26 15:31:15] Service ‘nginx’ restarted.  
Invalid entry: 2023/10/26 15:32:00  
[2023-10-26 15:35:45] WARNING: Disk space low.
```
Решение:
```r
\[\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}\]
```


#### 9. Исключающие наборы
Найдите знаки препинания. Вместо того, чтобы перечислять их все, напишите регулярное выражение, которое находит любой символ, но не букву, цифру или пробел.
Текст проверки:
```
Hello, world! How are you? I’m fine, thank you. (And you?)
```
Решение:
```r
[^a-zA-Z0-9 \(\)]
```



#### 10. Извлечение доменов
У вас есть список email-адресов. Напишите регулярное выражение, которое позволит извлечь из каждого адреса только доменное имя (часть после символа `@`).
Текст проверки:
```
test.user@example.com  
info@company.net  
support@help-desk.org
```
Решение:
```r
(?<=@)[a-zA-Z.-]+
```


### Группы и обратные ссылки

#### 11. Проверка парных конструкций
Найдите правильно сформированные простые HTML-теги, такие как `<h1>…</h1>` или `<strong>…</strong>`.
Текст проверки:
```
<p>This is a paragraph.</p>  
<b>This is bold.</b>  
<h1>This is a header.</h2>  
<i>This is italic but not closed.
```
Решение:
```regexp
<([a-zA-Z0-9]+)>.+<\/\1>
```


#### 12. Извлечение кодов
Из строк ниже нужно извлечь числовой код товара. Напишите выражение, которое создает захватывающую группу только для требуемых данных, но не для текстового префикса.
Должны извлекаться только коды, которым предваряет ИЛИ "Артикул", ИЛИ "Код товара".
Текст проверки:
```
Артикул: 00789  
Код товара: 98123-A  
Артикул: 55443
Тоже какой-то текст 123
```
Решение:
```
(?<=(?:Артикул|Код товара):) [0-9A-Z-]+
```


#### 13. Читаемость с именованными группами
Вам нужно разобрать (распарсить) структурированную строку лога, чтобы получить дату, событие и имя пользователя. Напишите читаемое регулярное выражение, используя именованные группы.
Текст проверки:
```
Дата: 2023-10-26; Событие: Вход; Пользователь: admin;
```
Решение:
```regexp
Дата:\s+(?<date>\d{4}-\d{2}-\d{2});\s+Событие:\s+(?<event>.+?);\sПользователь:\s+(?<user>.+);
```

#### 14. Позитивный просмотр вперед
Найдите все слова, за которыми сразу следует двоеточие, но не включайте его в само совпадение.
Текст проверки:
```
User: admin  
Status: success  
Action: login.  
Note the final dot.
```
Решение:
```regexp
[a-zA-Z0-9]+(?=:)
```


#### 15. Позитивный просмотр назад
Извлеките все числовые значения валют, которым предшествует знак фунта `£`, не включая в результат сам знак и другие посторонние символы.
Текст проверки:
```
The price is £50. The dollar price is $60. Another item costs £25.50.
```
Решение:
```regexp
(?<=£)[0-9]+(?:.[0-9]+)?
```


#### 16. Негативный просмотр вперед
Найдите все упоминания слова «отчет», за которыми не следует слово «готов».
Текст проверки:
```
Ежедневный отчет сформирован. Статус: отчет готов. Пожалуйста, проверьте последний отчет. Отчет за вчерашний день.
```
Решение:
```
отчет(?! готов)
```

#### 17. Негативный просмотр назад
Найдите все вхождения «error», если этому слову не предшествует «warning: » — обратите внимание на пробел после слова. Поиск должен работать независимо от регистра букв.
Текст проверки:
```
System Error: 404.  
Warning: Error: 503.  
An unexpected error occurred.  
Log entry: [Error]
```
Решение:
```regexp
(?<!warning: )\berror\b
```



#### 18. Границы слов в кириллице
Найдите все отдельные вхождения слова «задача» в тексте. Учтите, что стандартный маркер границы слова `\b` может некорректно работать с кириллицей в некоторых движках.
Текст проверки:
```
Это простая задача. Главная задача — решить все подзадачи. Усложним задачу: задача1.
```
Решение:
```regexp
(?<![а-яА-ЯёЁ])задача(?![а-яА-ЯёЁ])
```
