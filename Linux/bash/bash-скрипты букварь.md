
# Часть 1. Основы 

## 1. Shebang и запуск
Любой bash-скрипт должен начинаться со строки **shebang** (`#!`), которая указывает системе, какой интерпретатор использовать.
**Пример (`hello.sh`):**
```bash
#!/bin/bash
# Это комментарий. Скрипт выводит приветствие
echo "Привет, мир!"
```

**Как запустить:**
```bash
chmod +x hello.sh  # Делаем файл исполняемым
./hello.sh         # Запускаем
```

## 2. Переменные
В Bash нет строгой типизации. Переменные создаются присваиванием. **Важно:** вокруг знака `=` не должно быть пробелов.
**Пример (`variables.sh`):**
```bash
#!/bin/bash
# Объявление переменных
NAME="Алексей"
AGE=30

# Вывод переменных (используем $ для обращения к значению)
echo "Имя: $NAME"
echo "Возраст: $AGE"

# Встроенные переменные окружения
echo "Текущий пользователь: $USER"
echo "Текущая директория: $PWD"
```

## 3. Ввод данных от пользователя
Для чтения ввода используется команда `read`.
**Пример (`input.sh`):**
```bash
#!/bin/bash
# -p выводит подсказку, -s скрывает ввод (полезно для паролей)
read -p "Введите ваше имя: " USER_NAME
read -s -p "Введите пароль (не будет виден): " USER_PASS

echo "" # Перенос строки после скрытого ввода
echo "Вы ввели имя: $USER_NAME"
```


# Часть 2. Логика и циклы 

## 4. Условные операторы (if / else)

В Bash для условий чаще всего используют конструкцию `[[ ... ]]` (она безопаснее и поддерживает регулярные выражения, в отличие от старых `[ ... ]`).
_Операторы: 
`-eq` (равно), 
`-ne` (не равно), 
`-gt` (больше), 
`-lt` (меньше), 
`==` (строки равны)._
**Пример (`conditions.sh`):**
```bash
#!/bin/bash
FILE="test.txt"

# Проверка существования файла
if [[ -f "$FILE" ]]; then
    echo "Файл $FILE существует."
elif [[ -d "$FILE" ]]; then
    echo "$FILE - это директория."
else
    echo "Файл $FILE не найден."
fi

# Сравнение чисел и строк
NUM=10
if [[ $NUM -gt 5 && "$USER" == "root" ]]; then
    echo "Число больше 5 И вы root."
fi
```


## 5. Циклы (for и while)

Циклы позволяют обрабатывать списки, файлы или читать данные построчно.
**Пример (`loops.sh`):**
```bash
#!/bin/bash

# Цикл FOR: перебор диапазона
echo "--- Числа от 1 до 5 ---"
for i in {1..5}; do
    echo "Итерация $i"
done

# Цикл FOR: перебор файлов в директории
echo "--- Текстовые файлы ---"
for file in *.txt; do
    # Проверка, что файл вообще существует (защита от ошибки, если .txt нет)
    [[ -e "$file" ]] || continue 
    echo "Найден файл: $file"
done

# Цикл WHILE: чтение файла построчно
echo "--- Чтение /etc/passwd (первые 3 строки) ---"
COUNT=0
while read -r line; do
    echo "$line"
    ((COUNT++))
    [[ $COUNT -ge 3 ]] && break
done < /etc/passwd
```

# Часть 3. Продвинутые концепции

## 6. Аргументы скрипта (Позиционные параметры)
Скрипты могут принимать аргументы при запуске: `./script.sh arg1 arg2`.
**Пример (`args.sh`):**

```bash
#!/bin/bash
# $1 - первый аргумент, $2 - второй, $# - количество аргументов, $@ - все аргументы

if [[ $# -lt 2 ]]; then
    echo "Использование: $0 <имя> <возраст>"
    exit 1 # Завершаем скрипт с кодом ошибки 1
fi

echo "Привет, $1! Тебе $2 лет."
echo "Все переданные аргументы: $@"
```

## 7. Функции
Функции помогают структурировать код. Аргументы в функции передаются так же, как и в скрипт (`$1`, `$2`).
**Пример (`functions.sh`):**
```bash
#!/bin/bash

# Объявление функции
calculate_area() {
    local width=$1   # local - переменная видна только внутри функции
    local height=$2
    
    # Арифметические вычисления в $(( ... ))
    local area=$((width * height)) 
    echo "$area"
}

# Вызов функции и сохранение результата в переменную
RESULT=$(calculate_area 5 10)
echo "Площадь равна: $RESULT"
```

## 8. Подстановка команд (Command Substitution)
Позволяет сохранить вывод одной команды в переменную.

**Пример (`substitution.sh`):**
```bash
#!/bin/bash
# Старый синтаксис (обратные кавычки): `date`
# Новый синтаксис (рекомендуется): $(date)

TODAY=$(date +%Y-%m-%d)
FILE_COUNT=$(ls -1 | wc -l)

echo "Сегодня: $TODAY"
echo "Количество файлов в папке: $FILE_COUNT"

# Создание бэкапа
BACKUP_NAME="backup_${TODAY}.tar.gz"
echo "Создаем архив: $BACKUP_NAME"
# tar -czf "$BACKUP_NAME" ./*  # (Раскомментируйте для реального создания)
```

# Часть 4. Лучшие практики (Best Practices)

**Используйте "Строгий режим" (Strict Mode).** Добавьте в самое начало скрипта (после shebang) эту строку:
```bash
   set -euo pipefail
```

- `set -e`: Скрипт немедленно завершится, если любая команда вернет ошибку (код не 0).
- `set -u`: Ошибка при попытке использовать необъявленную переменную (защита от опечаток).
- `set -o pipefail`: Конвейер (`|`) вернет ошибку, если упадет _любая_ команда в цепочке, а не только последняя.

**Всегда заключайте переменные в двойные кавычки.** Используйте `"$VAR"` вместо `$VAR`. Это спасет от ошибок, если в переменной есть пробелы или спецсимволы. 
_Плохо:_ `rm -rf $DIR/` (если `$DIR` пуст, удалится корень `/`).
_Хорошо:_ `rm -rf "$DIR/"`

**Используйте `[[ ]]` вместо `[ ]`.** Двойные скобки безопаснее, не требуют экранирования и поддерживают логические `&&` и `||` внутри себя.

- **Используйте `local` в функциях.** Все переменные в Bash глобальны по умолчанию. Используйте `local var="value"`, чтобы не затереть переменные из основного кода.
- **Проверяйте результат `cd`.** Если `cd` не сработает, скрипт продолжит выполнение в старой директории, что может привести к катастрофе. 
	 _Плохо:_ `cd /var/log && rm *.log` 
	- _Хорошо:_ `cd /var/log || exit 1` (или используйте `set -e`).
- **Используйте длинные имена опций.** `mkdir --parents` понятнее, чем `mkdir -p`. Это улучшает читаемость кода.


# Часть 5. Наиболее частые ошибки
- **Пробелы вокруг знака `=`**
```bash
   # ОШИБКА: bash попытается запустить команду "VAR" с аргументами "=" и "value"
   VAR = "value" 
   
   # ПРАВИЛЬНО:
   VAR="value"
```

- **Отсутствие кавычек при работе с файлами/путями**
```bash
   # ОШИБКА: Если в имени файла есть пробел ("my file.txt"), цикл сломается
   for file in $(ls *.txt); do ...
   
   # ПРАВИЛЬНО: Используйте globbing напрямую
   for file in *.txt; do ...
```

- **Игнорирование кодов возврата (Exit Codes)** Многие пишут скрипты, где команды выполняются одна за другой, без проверки, успешно ли завершилась предыдущая. Использование `set -e` или явная проверка `$?` решает эту проблему.

- **Неправильное завершение heredoc**
```bash
   # ОШИБКА: Пробелы перед закрывающим EOF приведут к ошибке синтаксиса
   cat << EOF
       Text
       EOF 
```

- **Попытка изменить переменную внутри цикла `while` с пайпом**
```bash
   # ОШИБКА: Переменная COUNT не изменится, так как цикл работает в подоболочке (subshell)
   COUNT=0
   cat file.txt | while read line; do ((COUNT++)); done
   echo $COUNT # Выведет 0
   
   # ПРАВИЛЬНО: Используйте перенаправление ввода
   COUNT=0
   while read line; do ((COUNT++)); done < file.txt
   echo $COUNT # Выведет правильное число
```

- **Забытые закрывающие теги**
Забытый `fi` (для if), `done` (для циклов) или `esac` (для case) — самая частая причина синтаксических ошибок. Всегда проверяйте парность блоков.
