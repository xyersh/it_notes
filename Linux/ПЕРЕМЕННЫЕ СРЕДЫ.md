
### СВОЙСТВА
- **Формат данных:** Это всегда пары `ИМЯ=ЗНАЧЕНИЕ`. Значение всегда представляет собой **строку** (текст). Если программе нужно число, она сама преобразует строку в число.
- **Наследование (Inheritance):** Когда процесс (родитель) создает новый процесс (потомка), потомок **копирует** все переменные среды родителя.
- **Изолированность (Scope):** Изменение переменной среды в дочернем процессе **не влияет** на родительский процесс. (Например, если вы запустили скрипт и он изменил переменную, в вашем терминале она останется прежней).
- **Регистрозависимость:** `PATH` и `path` — это две совершенно разные переменные.
- **Соглашения об именах:** По негласному стандарту имена переменных среды пишутся ЗАГЛАВНЫМИ БУКВАМИ (например, `HOME`, `USER`, `PATH`), чтобы отличать их от локальных переменных оболочки.
- **Разделение на Shell и Environment:**
    - _Локальная переменная оболочки (Shell variable)_ — видна только в текущем терминале (bash/zsh).
    - _Переменная среды (Environment variable)_ — экспортируется и передается всем дочерним программам.

### Простое использование


**Просмотр:**
- `printenv` или `env` — показывает _только_ переменные среды (экспортированные).
- `set` — показывает _все_ переменные, включая локальные переменные оболочки и функции.
- `echo $ИМЯ` — выводит значение конкретной переменной (например, `echo $HOME`).

**Создание и изменение:**
```bash
# 1. Создаем локальную переменную (видна только в текущем shell)
MY_VAR="hello"
echo $MY_VAR  # выведет hello

# 2. Делаем её переменной среды (теперь она уйдет в дочерние процессы)
export MY_VAR
# ИЛИ сразу экспортируем при создании:
export MY_VAR="hello"

# Проверяем: запускаем новый shell (дочерний процесс)
bash
echo $MY_VAR  # выведет hello (наследование сработало)
```

**Удаление:**
```bash
unset MY_VAR  # удаляет переменную
```

**Передача переменной только для одной команды:** Если нужно передать переменную, но не засорять текущую среду, её пишут перед командой:
```bash
MY_VAR="test" ls -l
# Переменная MY_VAR будет доступна только процессу 'ls'. 
# После завершения ls она исчезнет.
```



### Сохранение и конфигурация
Переменные, заданные через `export`, живут только до закрытия терминала. Чтобы они сохранялись навсегда, их нужно прописать в конфигурационных файлах.

**Где хранить переменные:**
- **Для конкретного пользователя:**
    - `~/.bashrc` или `~/.zshrc` — загружается при открытии _каждого нового интерактивного терминала_.
    - `~/.profile` или `~/.bash_profile` — загружается только один раз при _входе в систему_ (login shell).
    - _Пример:_ `export PATH="$HOME/.local/bin:$PATH"`
- **Для всей системы (для всех пользователей):**
    - `/etc/environment` — читается PAM (системой авторизации) при входе. **Важно:** это не скрипт, а просто список `KEY=VALUE`. Здесь нельзя использовать подстановку переменных (например, `$HOME` здесь не сработает).
    - `/etc/profile` — системный аналог `~/.profile`.
    - `/etc/profile.d/*.sh` — папка, куда можно класть отдельные `.sh` скрипты с настройками среды (самый правильный способ добавлять системные переменные, например, при установке Java или Go).

### Автоматизация, Systemd, Контейнеры
Здесь мы выходим за рамки интерактивного терминала и настраиваем фоновые службы и контейнеры.

**Использование в Systemd (демоны и сервисы):** Если вы пишете `.service` файл для systemd, переменные среды из `.bashrc` не подхватятся, так как у systemd нет оболочки. Их нужно задавать явно:
```ini
[Service]
# Прямое задание
Environment="MY_APP_PORT=8080"
Environment="DB_HOST=localhost"

# Или подгрузка из файла (удобно для секретов)
EnvironmentFile=/etc/myapp/env.conf
```

**Использование в Docker и Kubernetes:** В контейнеризации переменные среды — главный способ конфигурации (принцип Twelve-Factor App).

- **В Dockerfile:** `ENV APP_ENV=production`
- **При запуске:** `docker run -e APP_ENV=production my_image`
- **Через .env файл:** `docker run --env-file .env my_image`

**Управление средой через утилиту `env`:**

- `env -i command` — запускает команду в **абсолютно чистой** среде (без `PATH`, `HOME` и т.д.). Полезно для отладки скриптов, чтобы убедиться, что они не зависят от скрытых настроек.
- `env -u VAR command` — запускает команду, принудительно удалив переменную `VAR` из среды.

### Безопасность и низкоуровневые нюансы
На этом уровне рассматривается то, как переменные среды влияют на безопасность и ядро Linux.

**1. Переменная `PATH` и безопасность (PATH Hijacking):** `PATH` указывает системе, где искать исполняемые файлы. Если злоумышленник добавит текущую директорию (`.`) в начало `PATH` (`export PATH=".:$PATH"`) и положит туда вредоносный скрипт с именем `ls`, то при вводе `ls` запустится вредоносный код, а не системная утилита. _Правило:_ Никогда не добавляйте `.` или директории с правами на запись для всех в начало `PATH`.

**2. Динамический линковщик (`LD_LIBRARY_PATH` и `LD_PRELOAD`):** Эти переменные указывают динамическому линковщику Linux (ld.so), какие библиотеки загружать в память.

- `LD_LIBRARY_PATH` позволяет подменить системные библиотеки на свои (например, для тестирования новой версии GCC).
- `LD_PRELOAD` позволяет загрузить свою библиотеку _до_ всех остальных, перехватывая вызовы системных функций (например, можно перехватить функцию `time()` и заставить любую программу думать, что сейчас 1970 год).

**3. Защита ядра (SUID/SGID):** Переменные `LD_PRELOAD` и `LD_LIBRARY_PATH` — мощное оружие для хакеров. Чтобы защитить систему, **ядро Linux игнорирует** эти переменные среды, если запускаемая программа имеет установленные биты `SUID` или `SGID` (то есть выполняется с правами другого пользователя, обычно root). Это предотвращает подмену библиотек в привилегированных утилитах (например, `sudo` или `passwd`).

**4. Переменные ядра и пространств имен (Namespaces):** В современных системах (особенно в контейнерах) переменные среды могут передаваться через механизмы ядра. Например, при использовании `unshare` или `nsenter` можно изолировать не только файловую систему и сеть, но и контекст выполнения, хотя сами переменные среды остаются атрибутом конкретного процесса, а не namespace'а напрямую.

### Методы использования (Шпаргалка)

| Задача                         | Метод / Команда                           |
| ------------------------------ | ----------------------------------------- |
| **Посмотреть все переменные**  | `printenv` или `env`                      |
| **Посмотреть значение**        | `echo $VAR_NAME`                          |
| **Задать локально (в shell)**  | `VAR="value"`                             |
| **Экспортировать в среду**     | `export VAR="value"`                      |
| **Передать в одну команду**    | `VAR="value" command`                     |
| **Удалить переменную**         | `unset VAR_NAME`                          |
| **Запустить в чистой среде**   | `env -i command`                          |
| **Сохранить для пользователя** | Добавить `export ...` в `~/.bashrc`       |
| **Сохранить для системы**      | Добавить `VAR=value` в `/etc/environment` |
| **Задать для systemd сервиса** | `Environment="VAR=value"` в `.service`    |




### ОСНОВНЫЕ ПЕРЕМЕННЫЕ СРЕДЫ LINUX

#### Пути и навигация 

Эти переменные определяют, где система ищет файлы и где вы находитесь.
- **`PATH`**
    - _Назначение:_ Список директорий (разделенных двоеточием `:`), в которых система ищет исполняемые файлы, когда вы вводите команду без полного пути (например, просто `ls` вместо `/bin/ls`).
    - _Пример:_ `/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin`
- **`HOME`**
    - _Назначение:_ Абсолютный путь к домашней директории текущего пользователя. К ней можно быстро обратиться с помощью тильды (`~`).
    - _Пример:_ `/home/username` или `/root`
- **`PWD`**
    - _Назначение:_ Текущая рабочая директория (Present Working Directory). Обновляется автоматически при использовании `cd`.
- **`OLDPWD`**
    - _Назначение:_ Предыдущая рабочая директория. Используется командой `cd -`, чтобы вернуться туда, где вы были до этого.
- **`MANPATH`**
    - _Назначение:_ Список директорий, в которых утилита `man` ищет страницы руководств (man pages). Обычно настраивается автоматически, но может быть полезно при установке специфичного софта в нестандартные папки.

#### Информация о пользователе и системе

Переменные, описывающие контекст, в котором работает пользователь.

- **`USER` / `LOGNAME`**
    - _Назначение:_ Имя текущего пользователя, вошедшего в систему.
    - _Пример:_ `ivan`
- **`SHELL`**
    - _Назначение:_ Путь к оболочке по умолчанию для текущего пользователя (то, что прописано в `/etc/passwd`).
    - _Пример:_ `/bin/bash` или `/bin/zsh`
- **`HOSTNAME`**
    - _Назначение:_ Имя компьютера (узла) в сети. Часто используется в скриптах логирования или в приглашении командной строки.
- **`UID`**
    - _Назначение:_ Числовой идентификатор пользователя (User ID). У `root` это всегда `0`.

#### Терминал и поведение оболочки

Эти переменные управляют тем, как терминал отрисовывает информацию и как оболочка (bash/zsh) парсит команды.

- **`TERM`**
    - _Назначение:_ Тип терминала (эмулятора). Сообщает программам (например, `vim`, `nano`, `tmux`), какие возможности отрисовки (цвета, курсор) поддерживает ваш терминал.
    - _Пример:_ `xterm-256color`, `screen`, `linux` (в консоли без GUI).
- **`PS1` (Prompt String 1)**
    - _Назначение:_ Строка приглашения ввода (то, что вы видите слева от мигающего курсора). Содержит специальные экранированные символы для цвета, имени пользователя, хоста и текущей папки.
- **`IFS` (Internal Field Separator)**
    - _Назначение:_ Внутренний разделитель полей. Определяет, какие символы оболочка считает разделителями слов при разбиении строк. По умолчанию это пробел, табуляция и перенос строки. Изменение `IFS` часто используется в bash-скриптах для чтения CSV или других нестандартных данных.
- **`EDITOR` и `VISUAL`**
    - _Назначение:_ Указывают текстовый редактор по умолчанию. Критически важны, когда другие программы (например, `git commit`, `crontab -e` или `visudo`) просят вас отредактировать конфигурацию.
    - _Пример:_ `nano`, `vim`, `code --wait` (VS Code).
- **`PAGER`**
    - _Назначение:_ Программа для постраничного просмотра длинного текста. Используется командами вроде `git log` или `man`.
    - _Пример:_ `less` или `more`.
- **`HISTSIZE` / `HISTFILESIZE`**
    - _Назначение:_ Определяют количество команд, сохраняемых в истории оперативной памяти (`HISTSIZE`) и в файле истории на диске (`HISTFILESIZE`, обычно `~/.bash_history`).



#### Локализация, язык и время

Переменные, отвечающие за то, на каком языке система общается с вами и как форматирует данные.

- **`LANG`**
    - _Назначение:_ Глобальная переменная локали. Задает язык системы, кодировку символов и форматы (даты, валюты).
    - _Пример:_ `ru_RU.UTF-8` или `en_US.UTF-8`.
- **`LC_ALL`**
    - _Назначение:_ "Переменная-диктатор". Если она задана, она **перекрывает** все остальные переменные локализации (`LC_CTYPE`, `LC_TIME`, `LANG` и т.д.). Часто используется хакерами или администраторами для принудительного запуска скриптов на английском языке: `LC_ALL=C my_script.sh`.
- **`TZ` (Time Zone)**
    - _Назначение:_ Часовой пояс для процессов. Позволяет запускать программы в другом времени, не меняя системные часы.
    - _Пример:_ `TZ="Europe/Moscow" date`.

#### Графический интерфейс (X11 / Wayland)

Эти переменные критичны, если вы работаете с GUI-приложениями или пробрасываете графику по SSH.

- **`DISPLAY`**
    - _Назначение:_ Указывает X-серверу (графической подсистеме), на какой экран отправлять окна.
    - _Пример:_ `:0` (первый локальный экран) или `localhost:10.0` (при пробросе графики через SSH X11 Forwarding).
- **`WAYLAND_DISPLAY`**
    - _Назначение:_ Аналог `DISPLAY`, но для современного графического сервера Wayland. Указывает на сокет Wayland.
- **`XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_CACHE_HOME`**
    - _Назначение:_ Часть спецификации Freedesktop.org. Указывают приложениям, где хранить конфиги, данные и кэш. Позволяют избежать мусора в домашней папке (например, храня все конфиги в `~/.config/`, а не плодя скрытые папки вроде `~/.mozilla`, `~/.vim` и т.д.).


#### Специальные (Bash/Shell) переменные

Это не совсем "переменные среды" (они не экспортируются в дочерние процессы по умолчанию), но они ведут себя как переменные и критически важны при написании скриптов.

- **`$?`** — Код возврата (Exit status) последней выполненной команды. `0` означает успех, любое число от `1` до `255` — ошибку.
- **`$$`** — PID (идентификатор процесса) текущего шелла. Часто используется для создания уникальных временных файлов (например, `/tmp/my_temp_file_$$`).
- **`$0`** — Имя запущенного скрипта или оболочки.
- **`$1`, `$2`, ... `$9`** — Аргументы, переданные скрипту при запуске (первый, второй и т.д.).
- **`RANDOM`** — При каждом обращении к ней генерирует случайное целое число от 0 до 32767.
- **`LINENO`** — Содержит номер текущей строки в скрипте. Очень полезно для отладки и логирования ошибок.
